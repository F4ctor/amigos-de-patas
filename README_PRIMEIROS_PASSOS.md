# ONG Adoção — Flutter/Dart + PostgreSQL

Esta versão corresponde ao arquivo ONG_Adocao_TCC_FLOAT_DOCK_v1.3.0.zip, com a persistência convertida de MySQL para PostgreSQL. Inclui aplicativo Flutter, painel administrativo web, API PHP com sessões e permissões, e os dados fictícios originais.

## 1. Execução local com Docker Compose

Na pasta que contém `compose.yaml`:

1. Copie `.env.example` para `.env` e preencha `DB_PASS` com uma senha própria para o banco.
2. Execute `docker compose up --build -d`.
3. API: `http://localhost:8080/ong_adocao/backend_api/`.
4. Painel: `http://localhost:8080/ong_adocao/painel_admin/login.html`.

O Compose inicializa o esquema e os dados de demonstração somente quando o volume PostgreSQL está vazio. Para parar mantendo os dados: `docker compose down`. As imagens enviadas pelo painel também ficam em volume persistente.

Conta fictícia da demonstração: `admin@ong.local`, senha `Admin@123`. Entre no aplicativo e altere a senha pelo perfil. Esse acesso é para demonstração local. Para uma instalação sem dados fictícios, remova a montagem de `002-demo.sql` do Compose antes da primeira execução e provisione seu administrador com hash gerado por `password_hash` no PHP.

## 2. PostgreSQL instalado + Apache/PHP (inclusive AMPPS)

O AMPPS pode continuar fornecendo Apache/PHP. Instale e inicie o PostgreSQL separadamente; phpMyAdmin não administra PostgreSQL.

No pgAdmin 4, crie um Login/Group Role chamado `ong_adocao`, com login habilitado e senha própria. Crie o banco `ong_adocao` com esse usuário como proprietário. Abra o Query Tool conectado ao banco como esse usuário e execute:

1. `database/ong_adocao.sql` — estrutura, índices e gatilhos.
2. Opcionalmente, `database/dados_demonstracao.sql` — conta e conteúdos fictícios originais; execute uma vez, em banco recém-criado.

Os scripts não apagam tabelas. A estrutura deve ser aplicada em banco vazio. Reexecutá-la em um banco existente gera erro e desfaz a transação, em vez de sobrescrever registros.

No PHP 8.1+, habilite `pdo_pgsql`, `mbstring` e `fileinfo`. Copie `backend_api/config/config.local.example.php` para `config.local.php` no mesmo diretório e preencha a senha. O arquivo local está excluído do Git. Reinicie o Apache após alterar o php.ini.

Copie `backend_api` e `painel_admin` para `www/ong_adocao` no AMPPS, preservando as duas pastas lado a lado. Para usar URLs sem `index.php`, habilite `mod_rewrite` e `AllowOverride All`. A alternativa é `backend_api/index.php?route=/animais`.

Na instalação manual, configure a porta real do Apache no aplicativo (a porta 8080 é o padrão do Compose). A porta 5432 é usada pela API para acessar o banco, não pelo aplicativo.

## 3. Abrir o aplicativo no Android Studio

**Abra a pasta `flutter_app`, que contém `pubspec.yaml`.** Este é um projeto Flutter. As orientações anteriores para abrir a raiz do projeto Kotlin não se aplicam a este arquivo.

Instale o Flutter SDK e os plugins Flutter/Dart. No terminal dentro de `flutter_app`:

```sh
flutter doctor -v
flutter pub get
flutter run
```

Por padrão, o emulador acessa `http://10.0.2.2:8080/ong_adocao/backend_api`.

Para um celular físico na mesma rede, substitua `192.168.1.15` pelo IPv4 real do computador e execute:

```sh
flutter run --dart-define=API_BASE_URL=http://192.168.1.15:8080/ong_adocao/backend_api
```

O computador precisa aceitar conexões à porta do Apache. Também é possível ajustar o valor padrão em `lib/config/api_config.dart`.

Para gerar APK com o endereço que o aparelho vai utilizar:

```sh
flutter build apk --release --dart-define=API_BASE_URL=http://192.168.1.15:8080/ong_adocao/backend_api
```

Saída: `flutter_app/build/app/outputs/flutter-apk/app-release.apk`.

Os arquivos Android e as versões de Gradle do anexo foram preservados. A compilação deve ser verificada com seu Flutter SDK. Não execute um script `preparar_android.bat`: esse arquivo era mencionado na documentação original, mas não estava no pacote.

## 4. O que mudou no banco

- Conexão PDO usa `pgsql`, porta 5432 e credenciais locais/variáveis de ambiente.
- IDs usam `GENERATED BY DEFAULT AS IDENTITY`; a API recebe cada ID com `RETURNING id`.
- ENUMs foram convertidos para textos com restrições CHECK.
- Flags permanecem 0/1 com CHECK, preservando os formatos esperados pelo aplicativo e painel.
- Índices e chaves estrangeiras do original foram preservados; há índice único adicional para e-mail sem distinção de maiúsculas.
- Gatilhos atualizam `data_atualizacao`; a conexão usa o fuso `America/Sao_Paulo`.
- Busca por nome, raça e descrição usa ILIKE para não distinguir maiúsculas/minúsculas. A comparação de acentos pode diferir da collation MySQL original.
- Sessões, autorização de administrador, uploads e funcionalidades existentes foram mantidos.

Essa conversão traz os dados fictícios incluídos no ZIP. Não importa automaticamente registros de outro servidor MySQL; para isso, é necessária uma exportação atual e um mapeamento de migração.

## 5. Testes

Consulte `VALIDACAO_DO_PACOTE.txt`. Para executar o teste da API local depois de subir o Compose:

```sh
python testes/test_api.py
```

O teste pressupõe os dados de demonstração e a senha inicial. Cria uma conta, um animal e uma solicitação identificados como teste, além de registros de sessão/auditoria. Use banco de testes.

Referências: [PDO PostgreSQL](https://www.php.net/manual/en/ref.pdo-pgsql.php) e [INSERT RETURNING](https://www.postgresql.org/docs/16/dml-returning.html).
